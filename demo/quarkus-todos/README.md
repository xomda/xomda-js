# `demo/quarkus-todos` — Quarkus 3 + Panache + JAX-RS

A **real, runnable** Quarkus 3 todo service. The app skeleton is
hand-written; the model-driven half (Panache entities, JAX-RS CRUD
resources, Java enums, Flyway V1 migration) is regenerated by xomda
before every build.

## Layout

```
demo/quarkus-todos/
├── README.md
├── pom.xml                                            ← hand-written
├── docker-compose.yml                                 ← hand-written (Postgres 16)
├── package.json                                       ← TS harness
├── scripts/build-templates.mjs                        ← authors .xomda/templates/Quarkus/*
├── .xomda/
│   ├── model.json                                     ← regenerated by `pnpm generate`
│   └── templates/Quarkus/                             ← entity, resource, enum, sql-schema
├── src/
│   ├── generate.ts, index.ts, __tests__/*.spec.ts     ← TS harness + Vitest render checks
│   ├── main/
│   │   ├── java/com/example/todos/HealthResource.java ← hand-written sample resource
│   │   ├── resources/application.properties           ← hand-written (Postgres prod config)
│   │   ├── generated/com/example/todos/               ← [gitignored] xomda-produced Java
│   │   │   ├── entity/{TodoList,Todo}.java
│   │   │   ├── enums/Priority.java
│   │   │   └── resource/{TodoList,Todo}Resource.java
│   │   └── generated-resources/db/migration/V1__init.sql   ← [gitignored] xomda-produced Flyway script
│   └── test/
│       ├── java/com/example/todos/TodoResourceTest.java    ← @QuarkusTest + REST-assured
│       └── resources/application.properties                ← test profile (H2 in PostgreSQL mode)
```

Hard rule (per the demo layout convention pinned in
[`docs/.backlog/demo-projects.md`](../../docs/.backlog/demo-projects.md)):
**generated code lives under `generated/`, hand-written code under `main/`,
tests under `test/` — never overlapping.** `src/main/generated/` and
`src/main/generated-resources/` are gitignored; every clone runs
`pnpm generate` before `mvn test`.

## Domain model

```
TodoList { id: uuid, name: string, createdAt: date }
Todo     { id: uuid, title: string, done: boolean,
           priority: Priority, list → TodoList, createdAt: date }
Priority { LOW, MEDIUM, HIGH }
```

## Run the tests

```bash
# 1. Vitest — fast in-memory render checks of the templates.
pnpm --filter @xomda/demo-quarkus-todos test

# 2. JVM — regenerate, then mvn test runs @QuarkusTest against H2.
pnpm --filter @xomda/demo-quarkus-todos generate
pnpm --filter @xomda/demo-quarkus-todos test:jvm
```

Both run as part of `pnpm test:demo` from the repo root (which
`pnpm test:all` chains after `pnpm test:jvm`).

## Run the app locally

```bash
pnpm --filter @xomda/demo-quarkus-todos generate
docker compose -f demo/quarkus-todos/docker-compose.yml up -d
mvn -f demo/quarkus-todos quarkus:dev
```

Then try the generated endpoints, e.g.:

```bash
curl -s http://localhost:8080/api/health
curl -s -X POST http://localhost:8080/api/todo-list \
  -H 'content-type: application/json' \
  -d '{"name":"Shopping","createdAt":"2026-05-22T10:00:00"}'
curl -s http://localhost:8080/api/todo-list
```

## Templates

Authored by [`scripts/build-templates.mjs`](./scripts/build-templates.mjs).
Re-run after tweaking the helper:

```bash
node demo/quarkus-todos/scripts/build-templates.mjs
```

Only model-driven artefacts are templated — the pom, application.properties,
docker-compose and the sample `HealthResource` stay hand-written so the
demo is a real Quarkus project, not a thin shell around a generator.
