# `demo/springboot-blog` — Spring Boot 4 + JPA + Flyway + Postgres

A **real, runnable** Spring Boot 4 service. The app skeleton is
hand-written; the model-driven half (JPA entities, repositories, services,
DTOs, Java enums, Flyway V1 migration) is regenerated by xomda before
every build.

## Layout

```
demo/springboot-blog/
├── README.md
├── pom.xml                                          ← hand-written
├── docker-compose.yml                               ← hand-written (Postgres 16)
├── package.json                                     ← TS harness
├── scripts/build-templates.mjs                      ← authors .xomda/templates/SpringBoot/*
├── .xomda/
│   ├── model.json                                   ← regenerated by `pnpm generate`
│   └── templates/SpringBoot/                        ← entity, dto, repository, service, enum, sql-schema
├── src/
│   ├── generate.ts, index.ts, __tests__/*.spec.ts   ← TS harness + Vitest in-memory render checks
│   ├── main/
│   │   ├── java/com/example/blog/BlogServiceApplication.java   ← hand-written entry point
│   │   ├── resources/application.yml                            ← hand-written (Postgres prod config)
│   │   ├── generated/com/example/blog/                          ← [gitignored] xomda-produced Java
│   │   │   ├── entity/{Author,Post,Comment}.java
│   │   │   ├── enums/PostStatus.java
│   │   │   ├── dto/{Author,Post,Comment}Dto.java
│   │   │   ├── repository/{Author,Post,Comment}Repository.java
│   │   │   └── service/{Author,Post,Comment}Service.java
│   │   └── generated-resources/db/migration/V1__init.sql        ← [gitignored] xomda-produced Flyway script
│   └── test/
│       ├── java/com/example/blog/BlogServiceApplicationTests.java   ← @SpringBootTest against H2
│       └── resources/application.yml                                ← test config (H2 in PostgreSQL mode)
```

Hard rule (per the demo layout convention pinned in
[`docs/.backlog/demo-projects.md`](../../docs/.backlog/demo-projects.md)):
**generated code lives under `generated/`, hand-written code under `main/`,
tests under `test/` — never overlapping.** `src/main/generated/` and
`src/main/generated-resources/` are gitignored; every clone runs
`pnpm generate` before `mvn test`.

## Run the tests

```bash
# 1. Vitest — fast in-memory render checks of the templates.
pnpm --filter @xomda/demo-springboot-blog test

# 2. JVM — regenerate, then mvn test runs @SpringBootTest against H2.
pnpm --filter @xomda/demo-springboot-blog generate
pnpm --filter @xomda/demo-springboot-blog test:jvm
```

Both run as part of `pnpm test:demo` from the repo root (which
`pnpm test:all` chains after `pnpm test:jvm`).

## Run the app locally

```bash
pnpm --filter @xomda/demo-springboot-blog generate
docker compose -f demo/springboot-blog/docker-compose.yml up -d
mvn -f demo/springboot-blog spring-boot:run
```

## Templates

Authored by [`scripts/build-templates.mjs`](./scripts/build-templates.mjs).
Re-run after tweaking the helper:

```bash
node demo/springboot-blog/scripts/build-templates.mjs
```

Only model-driven artefacts are templated — the app skeleton stays
hand-written so the demo is a real Spring Boot 4 project, not a thin
shell around a generator.
